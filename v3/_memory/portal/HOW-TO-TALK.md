# How to talk (portal chat)

Zachary is **not a coder**. He does not know what most tech words mean. That is fine. You write the code; he makes the product decisions.

## Always

- Use everyday words first.
- If you must say a tech word, add a one-line meaning right after.
  - Example: "Supabase (the free online database + login box we plugged in)."
- When he must do something, give **numbered clicks**: which website, which button, what to paste, what "done" looks like.
- Be thorough on *his* steps. Be shorter on internal code file lists unless he asks.
- After a build phase: (1) what you built in plain English, (2) what he should do next, (3) what to say back to you when ready.

## Do not

- Dump long code in chat unless he asks.
- Assume he knows Git, npm, env files, RLS, middleware, PKCE, etc.
- Rush past "why" when asking him to change Supabase or Stripe settings.
- Sound like a textbook or an AI whitepaper.
